# Bus：基础并行数据通道

Bus 是用户定义的并行 Data Signal 集合。每条通道保留独立的 Signal ID、Pattern、Start、数据间隔以及 Timing 关系。`D0` 等符号只是数据项身份标签，不是逻辑值或整组并行字。Bus 不要求 Clock，也不推断不同 Bus 之间的转换关系。

## 创建与数据

从 `Add → Bus` 设置名称、通道数（1–256）、Start 和数据间隔。Start 与间隔沿用现有的时间单位转换组件，内部统一保存为 ps。默认规则为前缀 `D`、起始编号 `0`、通道步进 `1`、时间步进等于通道数、长度 `3`。40 路 Bus 的第 0 通道因此是 `D0 D40 D80`，第 1 通道是 `D1 D41 D81`。

长度表示每条通道 Pattern 中的数据项个数。与普通 Data Signal 一致，Pattern 结束后从头循环，直到工程时长结束。每条通道的 Pattern 可以在展开后通过现有 Pattern Builder 单独编辑。

整体编辑器支持规则生成和表格粘贴。规则包含前缀、起始编号、通道步进、时间步进与生成长度，并预览前几条通道的前三个时间槽。表格按“一行一通道、一列一数据项”解析制表符分隔文本；行数必须与所选作用范围一致，所有行列必须完整且 Token 合法。任何错误都会给出行列位置，整次粘贴均不应用。

规则输入按起始数据、向下换通道、向右换时间槽组织；步进输入显示实时数据项示例，预览表格使用同样的行列方向。`View all` 打开完整规则预览，显示当前作用范围内全部通道及全部生成时间槽，支持横纵滚动并固定行列标题；此操作不应用数据修改。Bus、Clock 和 Data 标题共用选中效果：随调色板和明暗主题调整的中性背景与细轮廓，选中比悬停更明确。

批量操作明确选择“全部通道”或“选中通道”。默认保留已有局部 Pattern 修改；勾选替换后才会覆盖。对选中通道运行规则或粘贴，会建立这些通道的局部 Pattern 覆盖。

## 默认值与覆盖

Bus 保存 Start、数据间隔及生成规则。通道可分别覆盖这三个参数；属性面板标出继承状态，并提供“Restore bus default”。修改 Bus 默认值，只更新仍继承该参数的通道。缩减通道数会保留剩余通道 ID、设置和引用；删除的数据、Delay 和 Setup/Hold 数量会在操作前提示。依赖被删通道的 Derived Signal 会保留并显示缺失来源错误。

## 展示与 Timing

Bus 有折叠、精选和全部展开三种模式。新建时默认全部展开，只有用户主动选择精选或折叠才会收起通道；从标题按钮折叠再展开时恢复之前的展开模式。折叠仅占一行；精选可输入 `0–3, 38–39`，也可选前四路、奇数路或偶数路，并显示未展示数量。折叠和隐藏只改变视图，所有通道继续参加 Timing 计算。Bus 汇总行使用带双轨细节的波形段，按实际时间切换。连续编号时显示如 `D0–D39`、`D40–D79`；其他排列在宽度足够时列出完整序列，空间不足时显示开头与结尾的若干数据项，中间用省略号连接。悬停可查看按通道排列的完整标签。通道尚未全部开始时附带已开始/总通道数，避免误认为所有通道都有值。局部 Start、间隔和 Delay 造成的切换也会反映在汇总行。点击标题编辑 Bus，点击子通道名编辑该 Data Signal。波形区域仍用于拖动平移。

Bus 可整体排序、复制、隐藏、删除；普通 Signal 分组也可包含 Bus。复制后通道获得新 ID，Bus 内部引用改指向副本，指向外部 Signal 的来源保持不变。子通道使用现有 Data Timing 入口，Bus 本身没有聚合边沿。

工程 JSON 在现有 v3 Schema 下增加可选 `buses[]`，子通道仍位于 `signals[]` 并通过 `busId`、`busIndex` 关联。旧工程没有 `buses[]` 时按空集合读取，旧 Data 保持独立。SVG 按当前显示行导出，包括 Bus 摘要、展开的子通道、Clock 和可见 Timing 图形。
